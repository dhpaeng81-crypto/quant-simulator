# 구조와 설계

## 파일 구조

```
shared/            서버와 화면이 함께 쓰는 코드
  model.ts         예측 공식 (유일한 사본), 업종별 베타, 프리셋
  catalog.ts       기본 종목 10개, 업종 추정 규칙
  narrative.ts     AI가 없을 때의 규칙 기반 해설
  types.ts         타입
server/
  index.ts         Express API + 화면 제공
  backtest.ts      백테스트 (순수 함수, 네트워크 없음)
  http.ts          타임아웃 fetch, TTL 캐시
  sources/yahoo.ts    시세·과거 종가·종목코드 확인
  sources/naver.ts    종목 이름 검색(자동완성), 뉴스(공식 API)
  sources/gemini.ts   해설·시황 브리핑 (숫자는 만들지 않음)
src/
  App.tsx          상태와 레이아웃
  components/      TickerBar, BriefingCard, Watchlist, ScenarioPanel, ReportPanel, TrendChart, BacktestPanel
  lib/             api, format, storage(localStorage)
tests/             model, backtest 테스트
```

## API

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/health` | Gemini·네이버 키 설정 여부 |
| GET | `/api/macro?refresh=1` | 나스닥, 필라델피아 반도체, 원/달러, WTI (값·전일 종가·등락률) |
| GET | `/api/stocks?codes=005930,000660` | 종목 정보 + 시세 (최대 30개) |
| GET | `/api/stocks/search?q=` | 6자리 코드면 Yahoo로 확인, 이름이면 네이버 자동완성 → Yahoo 검색 |
| POST | `/api/narrative` | `{code, scenario, reference}` → 서버가 같은 공식으로 다시 계산한 뒤 해설 생성 |
| GET | `/api/news/:code` | 네이버 검색 API 뉴스 3건 (10분 캐시) |
| GET | `/api/commentary?refresh=1` | 시황 브리핑 (4시간 캐시, 새로고침은 10분 간격, 429면 15분 쉼) |
| GET | `/api/backtest/:code` | 최근 10거래일 백테스트 |

## 예측 공식 (`shared/model.ts`)

1. 입력을 대략 −5~+5로 맞춤
   - 환율: 전일 대비 % × 0.9 / 유가: 전일 대비 % × 0.22
   - 나스닥·반도체: 등락률 × 2 / 외국인 수급: 그대로 / 뉴스 분위기: ÷ 20 / 전일 등락률: 그대로
2. 점수 = Σ(업종 베타 × 입력). 베타 부호가 방향을 정함 (예: 환율 상승은 자동차 +0.45, 플랫폼 −0.55)
3. `pUp = sigmoid(0.5 × 점수)`, 신뢰도 지표 = max(pUp, 1−pUp)를 50~90으로 자름
4. 신호: 55 미만 중립, 75 이상 '강한'
5. 5일 참고선: 하루 변동 = 점수 × (1 − 0.15i) × 0.5 %

베타는 **학습한 값이 아니라 사람이 정한 값**입니다. 바꾸고 싶으면 `SECTOR_BETAS`를 고치고 `npm test`를 돌리세요.

## 백테스트 (`server/backtest.ts`)

- 최근 10개 한국 거래일 각각에 대해, 그날 장 시작 전에 알 수 있었던 값(그 날짜보다 **앞선** 마지막 미국 종가·환율·유가)과 전날 등락률로 공식을 돌림
- 외국인 수급·뉴스 분위기는 과거 값이 없어 0
- 보합일은 적중률 계산에서 제외. 비교 기준으로 '매일 상승이라고 했다면'의 적중률을 함께 보여 줌
- 전략: 상승 신호일만 보유, 비용·세금 제외

## 원본과 달라진 점

| 원본 | 지금 |
|---|---|
| 백테스트 예측이 **난수**(72% 확률로 '적중' 처리) | 같은 공식을 과거 실제 데이터에 적용 |
| 환율·유가 입력과 베타를 **둘 다 뒤집어서** 고환율이 자동차에 악재, 유가 상승이 대부분 업종에 호재로 계산됨 | 입력은 '오른 정도' 그대로, 방향은 베타가 결정 (테스트로 고정) |
| 확률 = 35 + 60·sigmoid → 점수 0에서 '상승 65%', 하락 신호는 35~65%로 표시 | 신뢰도 지표 50~90, 점수 0이면 50·중립 |
| 예측 공식이 서버·화면에 두 벌 | `shared/model.ts` 한 벌 |
| 종목 목록이 서버 전역 변수 → 한 사람이 지우면 모두에게서 사라짐 | 목록은 각자 브라우저에 저장 |
| 외국인 수급·감성 지수를 AI 검색/추정으로 채워 실측처럼 표시 | 값이 없음을 밝히고 직접 입력 |
| 뉴스 실패 시 **지어낸 헤드라인** 표시 | "가져오지 못함" 표시. 네이버 공식 검색 API 사용 |
| 백테스트·프롬프트에 날짜 `2026-05-30` 고정 | 실제 날짜 사용 |
| 'ML', '매수/매도 추천' 표기 | '규칙 기반 점수', '상승/하락 신호' |
| 확대 금지, 글자 크기 강제 덮어쓰기(버튼 11.5px) | 확대 허용, 본문 14px 이상, 터치 44px 이상 |
| HTTP 550 응답, 아이콘 외부 핫링크 | 표준 상태 코드, 아이콘 자체 포함 |

## 알려진 한계

- Yahoo·네이버 자동완성은 비공식 엔드포인트라 형식이 바뀌면 빈 결과가 됩니다.
- 10거래일 적중률은 표본이 작아 우연의 영향이 큽니다.
- 업종 추정은 이름 키워드 기반이라 새로 추가한 종목은 '기타 업종'으로 잡힐 수 있습니다.
